# Временный прототип в Portainer

`compose.prototype.yaml` запускает демонстрационный интерфейс и API с PostgreSQL 16.
Используется иллюстративная эвристика без оптимизатора. В интерфейсе доступны
подготовка сценария, история расчётов, KPI и таблица выпуска/дефицита по периодам.

## Новый stack

Нужны Portainer с Docker Standalone на Linux amd64 и доступ Docker-хоста к GHCR.
Оба образа публично доступны в GHCR и зафиксированы по digest; локальная сборка
и доступ к Docker Hub на сервере не требуются.

1. Выберите Environment → **Stacks → Add stack → Git repository**.
2. Имя stack: `pe-prototype` или другое свободное имя.
3. Repository URL: `https://github.com/ViacheslavKonov/polyethylene-production-planning`.
4. Repository reference: `refs/heads/main`; compose path: `compose.prototype.yaml`.
5. В **Environment variables** задайте собственный `POSTGRES_PASSWORD` прямо в Portainer.
   Необязательная переменная `WEB_PORT` меняет порт; по умолчанию — `8088`.
6. Нажмите **Deploy the stack**. Дождитесь статуса `healthy` у обоих контейнеров.

Вместо Git repository можно выбрать **Web editor** и вставить содержимое `compose.prototype.yaml`.
Миграции выполняются автоматически при старте; используйте одну копию приложения.

## Обновить уже запущенный прототип

Если stack создан из Web editor, замените его Compose обновлённым файлом и нажмите
**Update the stack**. Сохраните прежнее имя stack и прежний пароль БД:
volume с данными будет использован повторно. Если stack связан с Git repository,
используйте **Pull and redeploy** с compose path `compose.prototype.yaml`.

В прежнем файле привязка порта была `127.0.0.1:8088:8000`. Теперь по умолчанию
используется `0.0.0.0:8088:8000`. Если в переменных существующего stack есть
`WEB_BIND_ADDRESS=127.0.0.1`, измените её на `0.0.0.0` или удалите этот override.
Публикация обновлённого файла в GitHub сама по себе не обновляет stack из Web editor.

## Если Docker Hub возвращает ошибку сертификата

Ошибка `x509` с несовпадением имени `registry-1.docker.io` возникает при загрузке
образов Docker daemon на сервере. Это не сертификат веб-интерфейса; отключение
HTTPS приложения или настройки Compose не устраняют проверку сертификата Registry.

В текущем `compose.prototype.yaml` PostgreSQL, как и приложение, загружается из GHCR.
Используйте обновлённый файл и заново разверните stack; соединение с Docker Hub не потребуется.
Образ PostgreSQL соответствует прежнему официальному образу `postgres:16-alpine`
с digest `sha256:721873c34ceb9f8d8fc265984940dc982404c105f19ad51be9fdc5970a6080ea`.
Workflow `Publish prototype PostgreSQL` переносит проверенный образ для Linux amd64
в существующий публичный пакет GHCR; Compose фиксирует digest опубликованного образа.
Проверка TLS и контроль digest сохраняются. Имя БД, пароль, версия PostgreSQL и volume
при этой замене не меняются.

Если тот же сбой происходит и при доступе к `ghcr.io`, нужно исправить DNS,
настройки proxy или доверенную цепочку сертификатов на Docker-хосте; Compose
не может исправить сертификат, выпущенный для другого имени сервера.

## Открыть интерфейс

Откройте `http://<IP-или-имя-Docker-хоста>:8088/` в браузере своего компьютера.
SSH-туннель не требуется. Используйте адрес **Docker-хоста с приложением**;
он может отличаться от адреса сервера Portainer. При изменении `WEB_PORT` используйте выбранный порт.
Если доступ блокирует firewall или security group сервера, разрешите входящие подключения
к этому TCP-порту со своего компьютера.

Прототип доступен напрямую по HTTP без авторизации и TLS — это временный режим разработки
для синтетических данных. Порт PostgreSQL не публикуется. Для возврата к доступу
только с Docker-хоста установите `WEB_BIND_ADDRESS=127.0.0.1` и обновите stack.

## Проверить демо

При открытии страницы поля заполнены синтетическим примером. Нажмите
**«Сохранить и рассчитать»**. Ожидаемый результат:

- покрытие спроса — **96,65%**;
- выпуск — **15 260 т**;
- непокрытый спрос — **540 т**;
- переходные потери — **400 т**;
- в таблице — три недели.

Сценарий и результат сохраняются в PostgreSQL. Расчёт можно открыть через историю.
Результат не является оптимальным или технологически проверенным планом.
Health check: `GET /api/health`, ответ `{"status":"ok","database":"ok"}`.

## Сохранение данных

Используется volume `<stack-name>_pgdata`. Не удаляйте его при обновлении stack.
Изменение имени stack создаст отдельный volume. Изменение переменной `POSTGRES_PASSWORD`
в уже инициализированной БД само по себе не меняет пароль роли PostgreSQL.
Не меняйте пароль между повторными запусками без отдельной процедуры смены пароля в БД.
