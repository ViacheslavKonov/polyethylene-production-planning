# Polyethylene Production Planning

Открытый стартовый проект для **объёмного и календарного планирования производства полиэтилена**. Проект готов к развитию с Codex и развёртыванию **через Portainer (Docker Compose Stack)**.

> **Статус: инженерный каркас / демонстрация, НЕ производственная система.** Реализован только иллюстративный эвристический расчёт; нет полноценного оптимизатора, диспетчеризации, проверки физических ограничений, управления пользователями или безопасного внешнего доступа. Не используйте реальные технологические данные и не управляйте оборудованием с помощью этого ПО.

## Что уже работает

- Веб-интерфейс на русском: создание сценария на основе JSON и отображение KPI и плана по бакетам.
- REST/OpenAPI (`/docs`): сценарии, история расчётов, базовый расчёт потребностей/выпуска/дефицита/концевых запасов.
- PostgreSQL с Alembic-миграциями и постоянным Docker volume.
- Проверка входных данных: марки, периоды, допустимая детализация и горизонт планирования.
- Dockerfile, Portainer Stack, локальный Compose, GitHub Actions CI и GHCR publish.
- `AGENTS.md`, архитектура, трассировка требований и пошаговые задания для Codex.

## Уровни планирования

| Уровень | Целевой горизонт по ФТ | Минимальная детализация по ФТ | Результат |
|---|---|---|---|
| Объёмный годовой (ОГ ПП) | до 18 месяцев | месяц | План по маркам, потребностям и ресурсам |
| Объёмно-календарный (ОК ПП) | до 3 месяцев | неделя, допускается телескопический календарь | Более подробный план, заданное марочное колесо |
| Оперативный график | до 4 недель | сутки, допускается телескопический календарь | График на уровне конкретного агрегата и операций |

**Ограничения текущего прототипа:** SQL-хранилище позволяет сохранять сценарии всех трёх уровней, однако модель сейчас содержит только агрегированную ёмкость бакета, не описывает реальные агрегаты/силосы/потоки и использует фиксированную последовательность марок. Ни один план не считается технологически проверенным.

## Быстрый запуск локально

Установите Docker с поддержкой Compose. Из корня репозитория:

```bash
docker compose -f compose.dev.yaml up --build -d
```

Откройте `http://127.0.0.1:8088/` и API `http://127.0.0.1:8088/docs`.

```bash
curl -fsS http://127.0.0.1:8088/api/health
# {"status":"ok","database":"ok"}
```

Локальные тестовые учётные данные в `compose.dev.yaml` — **строго для разработки**; не используйте этот файл для постоянного/внешнего окружения. Для очистки: `docker compose -f compose.dev.yaml down` (без `-v`, если нужно сохранить БД).

## Portainer (после публикации образа)

1. Создайте **публичный GitHub repository** `ViacheslavKonov/polyethylene-production-planning` и загрузите в него содержимое стартового проекта.
2. GitHub Actions `Publish container` опубликует `ghcr.io/viacheslavkonov/polyethylene-production-planning:main`. Проверьте публичную доступность образа или настройте авторизацию Registry в Portainer.
3. В Portainer откройте **Stacks → Add stack → Git repository** и укажите URL репозитория, reference `refs/heads/main`, compose path `compose.yaml`.
4. Добавьте переменные `POSTGRES_DB`, `POSTGRES_USER`, **секретный** `POSTGRES_PASSWORD`, `APP_IMAGE`, `WEB_BIND_ADDRESS`, `WEB_PORT` (см. `.env.example`). **Не коммитьте секреты.**
5. Разверните stack. По умолчанию доступен только `127.0.0.1:8088` Docker-хоста. Для внешнего доступа потребуется настроенный reverse proxy с TLS и аутентификацией/контролем доступа; пока безопасный публичный веб-доступ не реализован.
6. GitOps Updates можно включить после настройки контроля версий образов и порядка обновления. Подробности — [`docs/PORTAINER.md`](docs/PORTAINER.md).
